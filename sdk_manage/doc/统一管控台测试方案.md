# 统一管控台测试方案（统一纳管 + SDK 控制面）

## 1. 测试目标

验证以下三点在生产发布前成立：

1. **全网节点仅通过本管控域完成纳管与规则下发**，核心链路不依赖第三方业务后台 HTTP API。
2. **控制面制品**与终端 SDK **二进制兼容**（路径、加密、JSON 字段）。
3. 原有主控能力（心跳、ACK、监控）在裁剪第三方接口后主路径仍可用。
4. （演进）**双种子入口 + 隧道按设备下发五元组** 时，与服务端/客户端 **`pickByUUID` 算法一致**，且 **签名校验** 生效。

---

## 2. 测试分层

| 层级 | 范围 | 工具建议 |
|------|------|----------|
| **单元测试** | Publisher 哈希路径、JSON 序列化、加解密与 SDK 对齐 | Go `testing`，共用 golden vector |
| **契约测试** | `remoteNodePayload` ↔ SDK `sanitizeNodeGroups` | Go 黑盒调用 `sdk` 包 |
| **集成测试** | DB → Publisher → 对象存储 mock → 下载解密 | `httptest` / MinIO / local file server |
| **E2E** | 真机或模拟器跑 SDK `Init→Prepare→Start` | Android 调试包 + `-tags sdkdebug` 日志 |

---

## 3. 单元测试用例（必选）

### 3.1 URL 与 MD5 与 SDK 一致（关键）

**目的**：杜绝管控发布路径与客户端 `buildNodeDataURLs` 不一致。

| 用例 ID | 输入 | 期望 |
|---------|------|------|
| UT-CP-01 | 固定 `date=20260510`、`app_name`、`sdk_version` | 生成的 COS/OSS/ZOS URL **字符串与 `sdk/controlplane.go` 完全一致** |
| UT-CP-02 | 边界：`app_name` 含数字、`sdk_version` 含主次版本 | 哈希变化符合预期（快照 golden） |

实现建议：从 `sdk` 抽 **纯函数** `BuildNodeDataURLsForTest(secret *SecretPayload)` 或与 Publisher 共享 `internal/controlpane`。

### 3.2 加密往返

| 用例 ID | 步骤 | 期望 |
|---------|------|------|
| UT-ENC-01 | Publisher 加密 → SDK `decryptNodeData` | 得到原始 JSON，`json.Unmarshal` 为 `nodesA`～`nodesE` |
| UT-ENC-02 | 明文 JSON 直传（联调模式） | SDK `tryPlainJSON` 分支可通过 |

### 3.3 节点条目合法性

| 用例 ID | 输入 | 期望 |
|---------|------|------|
| UT-NODE-01 | `nodesA` 中一项为 `1.2.3.4:443` | `sanitizeNodeList` 保留 |
| UT-NODE-02 | 非法字符串（无端口、空串） | 被过滤，不崩溃 |

### 3.4 隧道下发与设备选点（演进：与 `sdk/nodes.go` 同源）

**目的**：服务端「按设备只下发 A～E 各一条」时，与 SDK 本地 **`SelectFixedNodeSet`** 结果 **完全一致**（含组内节点顺序对取模的影响）。

| 用例 ID | 步骤 | 期望 |
|---------|------|------|
| UT-TUN-01 | 给定固定 `groups`、固定 `deviceUUID`，调用 SDK `SelectFixedNodeSet` 得基准五元组 | 隧道服务端 **同一输入** 产出 **相同五元组**（字符串逐项相等） |
| UT-TUN-02 | 互换某一组 `nodesK` 内 **两条顺序**（不改集合元素） | 同一 UUID 下该组选中节点 **按取模规则变化**，与服务端一致 |
| UT-TUN-03 | 伪造签名或篡改 payload | 客户端 **拒绝应用** |
| UT-TUN-04 | nonce/时间窗过期 | 客户端 **拒绝应用**（若协议启用防重放） |

实现建议：基准数据 **直接引用** `sdk.SelectFixedNodeSet`，隧道侧函数与之一致性测试 **合并进同一 CI job**。

## 4. 集成测试用例（必选）

### 4.1 发布流水线

| 用例 ID | 步骤 | 期望 |
|---------|------|------|
| IT-PUB-01 | 写入 DB 中五组各至少 1 个节点 → 触发 Publisher | 上传成功记录写入 `ControlPlanePublishRecord` |
| IT-PUB-02 | 模拟 COS 403 | 发布失败，事务回滚或标记失败，**无「半成功」静默状态** |
| IT-PUB-03 | 连续两次发布 | `content_sha256` 或版本号变化可追溯 |

### 4.2 SDK `Prepare` 拉取（Head/Get）

| 用例 ID | 步骤 | 期望 |
|---------|------|------|
| IT-SDK-01 | 本地 HTTPS 文件服务托管 `.dat`，Secret 指向测试路径（或通过代理重写 URL） | `resolveControlPlane` 成功，`Prepare` 返回 nil |
| IT-SDK-02 | 删除对象模拟 404 | `Prepare` 失败；配置 `app_domain` 后 **兜底成功**（需在测试 DNS 或 `/etc/hosts` 解析） |

### 4.3 Agent 与管控（不含第三方）

| 用例 ID | 步骤 | 期望 |
|---------|------|------|
| IT-AG-01 | Agent 注册 + 心跳 | Redis/DB 状态在线 |
| IT-AG-02 | 下发 `apply_rules` | 节点 ACK，`ConfirmedVersion` 更新 |

### 4.4 双种子 + 隧道（演进）

| 用例 ID | 步骤 | 期望 |
|---------|------|------|
| IT-TUN-01 | OSS 放置种子 blob、域名解析到同一 bootstrap | 客户端两条路径 **至少一条** 完成冷启动 |
| IT-TUN-02 | 种子连上后请求隧道配置（携带 device UUID） | 返回 **5 条 endpoint**，与 UT-TUN-01 基准一致 |
| IT-TUN-03 | OSS 种子缺失仅域名可用 | 仍可完成冷启动（验证冗余） |

### 4.5 静默刷新失败兜底（参见《客户端发现与静默切换逻辑》§5）

| 用例 ID | 步骤 | 期望 |
|---------|------|------|
| IT-FB-01 | 隧道返回的五元组经防火墙全部 dial 失败 | 触发 **重新拉种子** → **可选全量 Prepare** → **`app_domain`** 顺序中的前几步，无 tight loop |
| IT-FB-02 | 隧道 API 返回 429/5xx | **退避重试**，数据面连接仍可继续使用旧上游 |

## 5. 端到端场景（推荐）

| 场景 ID | 描述 | 通过标准 |
|---------|------|----------|
| E2E-01 | 新节点入库 → 划入 **nodesA** → 发布控制面 → **新安装 App** `Prepare` 成功并能 `Start` | 全链路无手工改 OSS |
| E2E-02 | 变更 **nodesB** 列表 → 再发布 → 清客户端缓存或等 HEAD 失效后 | 客户端固定集合更新（同一 UUID 下 B 组节点变化生效） |
| E2E-03 | 故意关停 COS/OSS，仅 ZOS 可用 | SDK 仍能 `fetchFastest` 成功（与线上一致） |
| E2E-04（演进） | 仅部署种子 OSS + 域名，无全量公开 `.dat` | 仍能通过隧道拿到五元组并完成业务连接 |
| E2E-05（演进） | 轮换池中某一组节点顺序后再下发 | 同一设备 UUID 选中节点变化符合 **取模规则**，且与 SDK 本地计算一致 |

## 6. 回归范围（相对旧测试策略）

沿用 `design.md` §测试策略 中的：

- JWT、PSK、规则 ACK 超时、心跳超时  
- **删除或降级**：「模拟第三方平台 HTTP」相关用例，改为 **Webhook mock（可选）**  
- **新增**：Publisher + SDK 控制面 **契约测试** 为 **CI 必跑**

## 7. 验收检查清单（发布前）

- [ ] UT-CP-01/02  green  
- [ ] UT-ENC-01 green  
- [ ] IT-SDK-01 green（至少一条真实 HTTPS 拉取链路）  
- [ ] 当日北京日期下 **三条存储 URL** 可在浏览器或 `curl` 下载且解密正确

- [ ] **无**「必须调用第三方业务 API」的配置项才能走完发布流程

## 8. 非功能测试（节选）

| 类型 | 说明 |
|------|------|
