# 统一管控台需求规格（与终端 SDK 对齐）

## 1. 文档目的与适用范围

本文档定义 **统一管控台** 的正式需求：在同一管理域内维护 **全部转发节点**、**Agent 控制通道与规则**，以及 **终端 SDK 可见的控制面制品**（加密 `.dat` 与域名兜底策略）。

**适用对象**：管控后台（API + UI）、Node Agent、控制面发布子系统（Publisher）。

**终端对齐**：仓库 **Go Mobile SDK**（`sdk/`）——`resolveControlPlane`、`decryptNodeData`、`nodesA`～`nodesE`、`SelectFixedNodeSet` / `pickByUUID`、`app_domain` 兜底（`sdk/controlplane.go`、`sdk/bootstrap.go`、`sdk/nodes.go`）。

**配套文档**：《统一管控台系统设计.md》《统一管控台测试方案.md》《客户端发现与静默切换逻辑.md》《独立控制连接与安全.md》。

---

## 2. 核心原则

| 原则 | 说明 |
|------|------|
| **全网单一管控源** | 节点生命周期、转发规则、上下线决策由 **本管控台** 及其 DB / 发布链路决定，**不依赖**外部「第三方业务后台 HTTP API」完成节点注册或注销。 |
| **外部通知可选** | 向 CMDB、工单等系统的 **HTTPS Webhook** 为可选能力，**不得阻塞**节点纳管、规则下发与控制面发布。 |
| **客户端发现保持 SDK 现状** | 终端 **不经由管控 REST 拉全量节点表**；通过 **COS/OSS/ZOS** 拉取加密 `.dat`，失败时用 **`app_domain` DNS** 兜底；管控负责生成并上传 **与 SDK 约定一致** 的制品与密钥策略。 |
| **五组节点模型** | 管控维护的池必须映射为 SDK 的 **`nodesA`～`nodesE`**，顺序与内容影响 `pickByUUID` 取模结果，须与发布流水线一致。 |

## 3. 术语与词汇表

### 3.1 核心术语

| 术语 | 含义 |
|------|------|
| **管控台** | 管理 UI + REST API +（可选）调度与发布 Worker；逻辑上可集群部署。 |
| **节点 / Agent** | 部署在转发机上的进程：TCP 转发、心跳与指标、接收规则、本地 WAL/快照。 |
| **业务线** | 可选的业务分类或路由归属维度（库存模型可沿用「Platform」表），用于筛选与调度策略；**不隐含**第三方注册接口。 |
| **控制面制品** | 经 AES 等与 SDK 一致的 **`remoteNodePayload`**，按 `buildNodeDataURLs` 路径写入 COS/OSS/ZOS 的 `.dat`。 |

### 3.2 技术与运行概念

| 术语 | 含义 |
|------|------|
| **ForwardRule** | 本地监听端口 → 目标 IP:Port；可附 **混淆参数**（TLS/HTTP/plain、限速、MUX 等）。 |
| **rule_version** | 全局单调递增整数；每次规则集合变更递增；与节点 **ConfirmedVersion**、**rule_ack** 对齐。 |
| **HealthMetrics** | 成功率、平均延迟、连接失败数、活跃连接、带宽等；随心跳上报。 |
| **ConfigVersion** | 某类资源配置的快照版本单元；支持历史查询与回滚。 |
| **GrayZone** | 新节点默认观察区；限流量运行，达标后晋升正式服务池。 |
| **Standby** | 备用区；故障转移时规则克隆的目标池。 |
| **ReputationScore** | 节点信誉分 0～100；参与调度排序与观察名单。 |
| **ProbeRTT / blackhole** | 管控对转发端口的主动 TCP 探活延迟；与心跳延迟严重不一致或高丢包时标记 **黑洞**，触发摘除与告警。 |
| **PlatformSchedulePolicy** | 业务线级调度策略：标签选择器、区域权重、单节点连接上限覆盖、是否启用信誉过滤等。 |
| **Webhook / DLQ** | 异步 HTTPS 通知；失败重试与 **死信队列** 人工处理；语义独立于「第三方平台 API」。 |

## 4. 功能需求

### 4.1 节点纳管与心跳（必选）

1. Agent 启动后 **注册**：节点 ID、监听地址、区域（A/B/C/D/备用/灰度等）、ISP、云厂商、标签等。
2. **心跳**默认间隔 **30s**（可配置），写入 Redis 等；载荷含 **HealthMetrics**。
3. **离线**：超过 **90s**（可配置）未收到心跳 → **离线**，界面与告警更新。
4. **质量降级**：成功率 **&lt; 0.90** 或平均延迟 **&gt; 500ms** → **质量降级**（仍在线）。
5. **控制通道**：**WebSocket 或 gRPC**；不得依赖外部 HTTP 作为心跳前置条件。
6. **重连**：断线后指数退避（最大间隔如 **60s**），优先连接当前 **Leader**。

### 4.2 转发规则与版本（必选）

1. 管理员配置 **转发规则**（本地端口 → 目标）；支持启用/停用、**批量下发**；节点 **多端口并发**。
2. **rule_version** 全局单调递增；节点成功后 **`rule_ack`**；管控持久化 **ConfirmedVersion**。
3. **ACK 超时**：首次下发后 **10s** 内无 ACK → 重发同一版本；**最多再试 3 次**、间隔 **5s**；仍失败 → **配置异常** + **`rule_ack_timeout`** 告警。
4. **幂等**：若 `rule_version` ≤ 节点已应用最大版本 → **丢弃载荷**，仍 ACK **当前版本**。
5. **Leader 切换**：新 Leader 读取各节点 ConfirmedVersion，对落后节点 **补发** `apply_rules`。
6. **切换时效**：规则变更宜在 **≤5s** 内完成旧监听释放与新监听建立；端口占用 → 上报 **端口冲突**，节点标记 **配置异常**。
7. **心跳指标**：每条活跃规则在心跳中携带聚合指标（成功率、失败连接数、RTT 等），供调度与告警使用。
8. **WAL + 快照**：变更先写 **WAL** 再应用；周期快照（如 **60s**）；重启：**快照 → 回放 WAL → 请求管控同步**；管控不可达时 **本地规则降级运行**。

### 4.3 控制面发布（必选）

1. **制品 JSON**：与 `sdk/controlplane.go` 中 **`remoteNodePayload`** 一致：`nodesA`～`nodesE`（`host:port` 合法）。
2. **加密**：与客户端 Secret 中 **AES** 一致，算法分支与 **`decryptNodeData`** 一致。
3. **对象路径**：按 **`buildNodeDataURLs`**（北京日期、`app_name`、`sdk_version`、`cos_appid` 等）生成三云 URL；支持一键发布或 CI 定时发布。
4. **`app_domain`**：管控维护与 Secret 一致的泛域名策略说明，供运维配置 DNS 兜底。

### 4.4 监控与告警（必选）

1. **节点面板**：在线/质量/配置状态、区域、ISP、云、业务线（若建模）、规则数、最后心跳、HealthMetrics、信誉分（功能开启时）、ProbeRTT（探活开启时）。
2. **集群面板**：Leader、成员、节点计数、灰度/备用计数、活动告警数。
3. **视觉区分**：不可用、质量降级、配置异常、**blackhole** 等醒目标记。
4. **心跳历史**：查询能力，建议保留 **7 天**（可配置）。
5. **分组视图**：按区域、ISP、云、标签筛选。
6. **告警类型**（至少）：节点离线；备用耗尽；质量持续低于阈值（如持续 **5 分钟**）；**`blackhole_detected`**；**`rule_ack_timeout`**；**控制面发布失败**；低利用率（功能开启时）。
7. **Webhook**：可选推送；告警恢复后可标记 **已解决**。

### 4.5 管理安全与高可用（推荐）

量化细则见 **§4.9**；本节为摘要。

1. 管理员 **JWT + RBAC**；Agent **PSK** 或 mTLS。
2. 管控集群 **Raft/etcd** 选主；Leader 执行调度与发布写路径。
3. **审计**：配置变更、发布记录、管理员操作。

### 4.6 调度、灰度与多租户相关能力（分期）

下列能力 **分期交付**；一期以「节点纳管 + 规则 + 控制面发布」为主。

| 能力 | 要求摘要 |
|------|----------|
| **智能调度** | 综合评分（权重、延迟、成功率、连接、带宽、信誉）；同 Zone 优先；可跨 Zone/ISP/云 **降级调度** 并记日志；标签选择器；单节点连接数 **&gt; 上限 80%** 时跳过新分配；信誉 **&lt;30** 可不进正式区调度。 |
| **业务线策略** | 每业务线可配置 **PlatformSchedulePolicy**（标签、区域权重、连接上限覆盖、信誉过滤开关）。 |
| **灰度** | 新节点默认灰度区；观察流量如 **≤10%**；观察窗口 **10～30 分钟**（可配）；达标晋升；不达标 **灰度失败** + 告警；正式区失败率在滑动窗口超阈值可自动摘除；支持手动晋升/降级。 |
| **标签** | 节点 KV 标签；业务线级标签选择器；变更后重算调度池；支持组合查询。 |
| **限流与熔断** | 管理 API **按租户限流**；对 **Webhook 目标** 熔断（典型：**60s** 内失败 **&gt;5** → 断开，**30s** 后半开探活）。 |
| **多租户** | 租户数据隔离、超级管理员、API 配额；强隔离可后置。 |
| **信誉分** | 初值如 **80**；事件驱动增减；**&lt;30** 入观察名单（不参与正式区调度，可作备用）。 |

### 4.6.1 故障转移、黑洞与成本（分期）

| 类别 | 要求摘要 |
|------|----------|
| **故障转移** | 离线或策略摘除 → 不可用；从 **备用区** 选节点 **克隆规则**；成功后代偿；无备用 → **告警**；记录 **FailoverLog**。 |
| **失败率摘除** | 转发失败率超阈值（默认 **0.20**，可配）→ 自动摘除并转移。 |
| **黑洞** | 周期（如 **60s**）TCP 探活；**ProbeRTT** 与自报延迟差 **&gt;200ms** → 延迟异常告警；丢包率超阈值（如 **30%**）→ **`blackhole`** + 转移；恢复后建议回 **灰度** 再观察。 |
| **成本** | **NodeUtilization** 统计；连续 **6 小时**低于阈值（如 **10%**）→ 低利用率告警；回收：**规则迁移** + 审计日志；自动回收默认关闭。 |

### 4.7 演进：双入口种子 + 按设备下发固定五元组（推荐）

1. **冷启动双入口**：OSS/COS/ZOS **种子桶** 与 **`app_domain` 同类域名** 并列，仅存 **极简种子**（单入口或短加密载荷），与全量五组 `.dat` 曝光策略区分。
2. **控制连接**：独立 TLS，与 Relay **同端口**、**ALPN** 分流；HELLO/HMAC、PUSH、PSK 见 **《独立控制连接与安全.md》**。
3. **非全量下发**：连通后按 **device UUID** 下发 **A～E 各一条** endpoint（与 **`pickByUUID`** 同源或下发已签名五元组），详见系统设计 §2.1。
4. **完整性**：隧道与控制载荷须带 **HMAC/签名**；客户端校验失败不得应用。

与「对象存储全量 `.dat`」可通过特性开关 **并存**，逐步收紧公开面。

### 4.8 业务线、源站与配置版本（可选）

1. **业务线与源站**：CRUD、租户归属、源站列表与 **优先级**；删除前校验是否仍有关联节点。
2. **ConfigVersion**：每次变更生成快照与摘要；支持历史与 **回滚**；建议每资源保留最近 **50** 个版本。
3. **连通性探测**：对运维配置的 URL 做探测（状态码与耗时），**不作**节点对外注册接口。
4. **回滚失败**：告警与审计，不自动重试回滚事务本身。

### 4.9 认证、Agent 鉴别与集群 HA

1. **管理员**：用户名密码；密码 **bcrypt**；会话 **JWT**（如 **24h**）；参数来自 **YAML**（数据库、Redis、etcd/Raft、监听、JWT 密钥、PSK 等）。
2. **Agent**：控制通道 **PSK** 或 mTLS；非法拒绝接入。
3. **集群**：实例 **≥3**；**etcd 或 Raft** 选主；Leader 故障 **约 10s** 内完成切换（依赖具体参数）；选举中 **写 503**、读可继续；**Redis**（或等价）共享节点在线视图；提供集群健康接口；新成员经日志复制后加入。

### 4.10 Agent 侧转发与混淆

规则载荷可携带 **ObfuscationConfig**：**TLS / HTTP / plain**；随机端口范围；连接 **复用（MUX）**；**带宽限速**；可选 **随机填充**；源 IP **滥用连接限流**。具体字段与系统设计 §3.2.1 消息示例一致。

## 5. 一期非主线边界

| 项目 | 说明 |
|------|------|
| 第三方业务 HTTP 注册 | **不作为**闭环必要条件；需要时用 Webhook，失败重试，**不阻断**纳管与 `.dat` 发布。 |
| SDK 直连管控拉表 | 一期不要求 SDK 轮询管控 REST；仍以对象存储 + 域名为准。 |
| 每租户一套外部账户 | 不引入多套外部平台账号体系；租户主要指数据隔离与配额。 |

---

## 6. Webhook 与异步通知

事件（上下线、告警、故障转移等）可异步 **POST JSON** 到配置的 HTTPS URL：**最多 3 次**重试（间隔如 **10s**）、**DLQ** 可查与手动重试、按目标 **熔断**；每次调用记录请求/响应/耗时。**不强承诺**实时送达，以队列最终一致为准。

## 7. 验收口径

| 编号 | 验收说明 |
|------|----------|
| AC-U1 | 新增/变更节点与分组后，在规定延迟内完成控制面发布，SDK **`Prepare`** 能拉取并成功解密，业务可达（网络与密钥正确前提下）。 |
| AC-U2 | **不依赖**任何第三方业务 HTTP，即可完成：节点入库 → 规则下发 → 客户端可见制品（可选 Webhook 不计入必选路径）。 |
| AC-U3 | 制品中 **五组列表** 与 **`pickByUUID`** / `SelectFixedNodeSet` 兼容（同一 device UUID 下稳定）。 |
| AC-U4 | 人为制造对象存储失败时，SDK 可走 **`app_domain`** 兜底（与运维 DNS 一致）。 |
| AC-U5 | 心跳超时后节点显示离线；质量阈值触发「质量降级」状态。 |
| AC-U6 | `rule_version` 递增；节点 **`rule_ack`** 与 DB 中 **ConfirmedVersion** 一致；ACK 超时产生可观测告警。 |
| AC-U7 | Leader 切换后，落后节点收到 **补发**规则并最终一致。 |
| AC-U8 | Agent 本地 WAL+快照：重启后规则与切换前一致（在同版本约束下）；管控不可达时可继续转发（降级模式）。 |
| AC-U9 | 发布失败（上传失败或哈希校验失败）可告警且可追溯发布记录。 |
| AC-U10（演进） | 启用隧道下发后，五元组与 **`sdk/nodes.go`** 算法一致或验签通过（见测试方案）。 |
| AC-U11（演进） | 种子级 OSS + 域名策略下，公开对象不包含未授权的完整五池明文（策略可配置）。 |
