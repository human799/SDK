# SDK 状态机与韧性策略

## 为什么要状态机

“能连/不能连”的二值策略不适合商用，必须让不同故障阶段使用不同策略。

## 状态定义

- `NORMAL`：固定主节点，低频探测
- `DEGRADED`：探测加频，准备回退
- `ATTACK`：快速止损，熔断失效节点
- `RECOVERING`：半开探测，逐步恢复
- `EMERGENCY`：固定集合与 DNS 都失败，进入低频保活

## 熔断策略

每节点维护 `Closed/Open/Half-Open`：

- 连续失败达到阈值 -> `Open`
- 到期试探 -> `Half-Open`
- 成功恢复 -> `Closed`

## 退避策略

建议：`1, 2, 4, 8, 16, 30, 60` 秒，上限后保持 60 秒，并加入抖动。

## 边界约束

状态机和熔断只在固定 5 节点集合内生效，不扩节点范围。
